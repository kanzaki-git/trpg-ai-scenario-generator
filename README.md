# TRPG AIシナリオ生成サービス

**TRPGを遊んでみたい。でも、シナリオの準備やGMの進め方が分からない。**

そんな人が、友人と物語を楽しむ最初の一歩を踏み出すためのWebサービスです。

ジャンル・世界観・雰囲気・プレイヤー人数・プレイ時間を入力すると、AIが**シナリオとGM向け進行ガイド**を生成します。生成後は、シーンや手がかりを確認しながらセッションを進行でき、プレイヤーには専用画面で必要な情報だけを共有できます。

**サービスURL：** https://trpg-ai-scenario-generator.onrender.com/

> **ご利用にあたって** 生成されたシナリオは、GMが内容や整合性を確認・調整して利用することを想定しています。シナリオ生成には利用回数の上限があります。また、無料ホスティング環境のため、初回アクセス時に起動時間がかかったり、データベースの利用期限によってサービスが利用できなくなったりする場合があります。

## サービス概要

本サービスは、AIを使ってTRPGのシナリオ準備とGM（ゲームマスター）の進行を支援するアプリケーションです。

生成されるシナリオには、導入、シーンごとの目的・読み上げ文章・進行ガイド、NPC、調査場所、手がかり、イベント、シーン遷移条件、エンディングなどが含まれます。

AIがセッションを自動進行するのではなく、**GMがプレイヤーの行動に応じて物語を進める**ことを前提としています。AIは、そのための準備資料を提供します。

## 開発背景

私はTRPGの配信やリプレイ動画を見ることが好きで、自分でも友人と遊んでみたいと思っていました。しかし、実際に始めようとすると、ルールを理解すること、自分たちに合うシナリオを探すこと、GMとして当日の進行を準備することなど、多くの工程が必要でした。

特にGM未経験者にとっては、「どのタイミングで情報を出すか」「プレイヤーに何を問いかけるか」「参加者が迷ったときにどう対応するか」といった点が分かりづらいと感じました。

私が魅力を感じたのは、友人と一緒に行動を選び、物語を作り上げる体験そのものです。そこで、**シナリオを生成するだけでなく、GMが当日どう進めればよいかまで分かるサービス**を開発しました。

## 想定ユーザーと解決したい課題

**想定ユーザー**

- TRPG配信やリプレイ動画を見て興味を持ったが、まだ遊んだことがない人
- 友人とTRPGを遊びたいものの、準備に負担を感じている人
- GMに挑戦したいが、セッションをどう進めればよいか不安な人

**解決したい課題**

> 物語を作りながら遊ぶ体験に興味を持った人が、準備や進行への不安によって最初の一歩を踏み出せないこと。

本サービスでは、条件の入力からシナリオ準備、セッション中の情報管理までを一つの流れにまとめ、この負担を減らすことを目指しています。

## 主な機能

### 1. AIによるシナリオ生成

- ジャンル、世界観、雰囲気、プレイヤー人数、プレイ時間を指定して生成
- 導入・シーン・NPC・手がかり・イベント・エンディングを構造化して保存
- GM向けの読み上げ文章、進行ガイド、探索の案内、シーン遷移条件を表示
- シナリオ一覧・詳細の閲覧、不要なシナリオの削除
- 生成回数の上限表示と、生成状態・失敗時の管理

### 2. GM向けセッション進行支援

- セッションの現在地を選択
- 提示済みの手がかり、訪問済みの場所、登場済みNPCを記録
- NPCの配置や探索先、発生イベント、移動条件を参照
- 共通マップで場所と経路を確認
- 秘密の場所をセッション単位でプレイヤーへ公開・公開解除

### 3. プレイヤー専用画面

- 専用URLから現在地、共通マップ、登場済みNPCを確認
- 約5秒間隔で情報を自動更新（ページ再読み込み不要）
- GMが公開した場所をマップへ追加し、公開解除された場所を非表示にする
- 未公開の場所や秘密の経路はプレイヤー向け表示から除外

### 4. シナリオ紹介ページの共有

- シナリオの公開用タイトル・紹介文を設定
- ログイン不要の紹介ページをURLで共有
- 公開・非公開を切り替え可能
- DiscordやLINEなどでのリンク共有を想定したOGP対応

### 5. アカウント・利用案内

- ユーザー登録、ログイン、ログアウト
- 利用規約・プライバシーポリシーの掲載

## 使い方

1. [サービスにアクセス](https://trpg-ai-scenario-generator.onrender.com/)し、ユーザー登録・ログインします。
2. 「新しいシナリオを作成」からジャンル・世界観・雰囲気・人数・時間を入力します。
3. AIの生成が完了したら、シナリオ概要・NPC・手がかり・シーン・エンディングを確認します。
4. GMは「シーン進行」画面を開き、読み上げ文章や進行ガイドを参考にセッションを進めます。
5. 「セッション進行」パネルで現在地、提示済みの手がかり、登場済みNPCなどを更新します。
6. プレイヤー専用URLを参加者に共有します。プレイヤー画面には公開可能な情報だけが表示され、変更は自動反映されます。
7. 必要に応じて、別途シナリオの紹介ページを公開し、セッション前に参加者へ共有します。

> プレイヤー専用画面はセッション中の情報共有用です。シナリオ紹介ページはセッション前の紹介用で、用途が異なります。

## 実装で工夫したこと

### AI生成結果を扱いやすいデータとして保存

生成結果を単なる長文として表示するのではなく、シーン、NPC、手がかり、イベント、場所などの関連データとして保存し、GMが必要な情報を画面ごとに参照できるようにしました。生成中・完了・失敗といった状態も管理しています。

### GM用情報とプレイヤー用情報の分離

GM向けのネタバレ情報がプレイヤー画面に表示されないように、公開可能な場所・経路・NPCをサーバー側で絞り込んでいます。秘密の場所はシナリオ自体の公開設定を書き換えるのではなく、セッション単位の中間テーブルで公開状態を管理しています。

### Stimulusを使ったセッション情報の自動更新

プレイヤー画面は一定間隔でステータスAPIを取得し、現在地・NPC・マップを必要に応じて更新します。通信の重複防止、タブ非表示時の停止、通信失敗後の再試行にも対応しました。

### データの整合性とテスト

進行状況の更新にはトランザクションを使用し、途中でエラーが発生した場合にデータが部分的に更新されないようにしています。Controller・Modelのテストに加えて、RuboCop・BrakemanをGitHub Actionsで実行しています。
