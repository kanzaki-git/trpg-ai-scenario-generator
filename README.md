# TRPG AIシナリオ生成サービス

## 1. サービス概要

TRPG配信やリプレイ動画を見て興味を持ったものの、ルール理解やシナリオ準備の負担によって、実際には遊び始められていない人向けのWebサービスです。

ユーザーは、ジャンル、世界観、雰囲気、プレイ人数、プレイ時間などを入力するだけで、AIがセッションで利用できるシナリオの土台を生成します。

生成される内容には、以下の要素が含まれます。

* 導入
* シーンごとの進行
* 登場人物（NPC）
* 発見できる手がかり
* イベント
* 真相
* エンディング候補
* GM向け進行ガイド

シーンごとの進行には、各シーンの目的、GMが説明する内容、GMが行うこと、プレイヤーへの質問例、入手できる情報、次のシーンへ進む条件などを含めます。

AIは、シナリオの土台とGM向けの進行ガイドを作成します。

ゲームマスター（GM）は生成された内容を確認し、必要に応じて調整したうえで、参加者の行動に応じた状況説明、NPCの演技、情報の提示、物語の進行を担当します。

プレイヤーはそのシナリオをもとに行動や選択を行い、GMの進行によって物語を楽しみます。

物語をみんなで作り上げる楽しさはそのままに、シナリオ探しやGMの準備負担を減らし、「遊びたい」と思ったその日に友人と遊び始められる環境を提供します。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

私はTRPGの配信やリプレイ動画を見ることが好きで、自分でも友人と遊んでみたいと思っていました。

しかし、実際に始めようとすると、ルールブックの購入やルール理解、自分たちに合ったシナリオ探し、ゲームマスターによる事前準備など、多くの工程が必要でした。

また、シナリオを用意できたとしても、GM未経験者にとっては、

* どのように物語を始めればよいのか
* どのタイミングで情報を出せばよいのか
* プレイヤーに何を問いかければよいのか
* 参加者が迷ったときにどう対応すればよいのか

といった、当日の進行方法も分かりにくいと感じました。

その結果、「面白そうなのに始めるまでが大変」と感じ、結局遊ぶまでに至らなかったことがあります。

私が魅力を感じていたのは、細かなルールやシステムではなく、友人と一緒に物語を作りながら遊ぶ体験そのものでした。

そこで、シナリオだけではなく、GMが当日どのように進めればよいかまで分かる仕組みがあれば、多くの人が気軽に遊び始められるのではないかと考え、このサービスを思いつきました。

### 2-2. なぜそれが気になったのか

私はゲームや娯楽を楽しむ際に、できるだけ手軽に始められることを重視しています。

面白そうなコンテンツであっても、始める前の準備や学習コストが高いと、興味を持った人が途中で諦めてしまう場面を何度も見てきました。

物語を作りながら遊ぶ体験には大きな魅力があります。

しかし、その魅力に触れる前の準備段階や、「自分にGMができるのだろうか」という不安によって離脱してしまう人も少なくありません。

私は「やってみたい」と思った人が、その気持ちのまま遊び始められる環境を作りたいと考えています。

物語を作りながら遊ぶ体験に興味を持っても、ルール理解、シナリオ探し、事前準備、当日の進行方法の確認などが必要になり、気軽に始めることができない。

### 3-2. 本当に解決したい課題は何か

なぜ？

→ 遊び始める前に準備することが多いから

なぜ？

→ 初心者にとって何から始めればよいか分からないから

なぜ？

→ ルールを覚えたり、シナリオを探したり、GMとしての進行方法を考えたりする負担が大きいから

なぜ？

→ 「やってみたい」という気持ちはあっても、実際の行動へ移せないから

### 本当に解決したい課題

**物語を作りながら遊ぶ体験に興味を持った人が、準備や進行への不安によって最初の一歩を踏み出せないこと。**

### 4-2. 自分とユーザーの距離

過去の自分です。

私自身がTRPG配信を見て興味を持ちながらも、ルール理解やシナリオ探し、準備の負担によって、実際に遊ぶまで至らなかった経験があります。

また、シナリオを用意した後に、GMとしてどのように進行すればよいか分からないことも、始めにくさの一つだと感じていました。

### 4-3. 実際に使われる可能性について

最初に利用してくれるのは、物語を作りながら遊ぶ体験に興味を持ったものの、準備の多さやGMへの不安によって、まだ遊べていない人だと考えています。

本サービスは、物語生成そのものではなく、**「初心者でもセッションを始められる状態を作ること」**に価値があります。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

1. ユーザーがジャンル、世界観、雰囲気、人数、プレイ時間を入力する
2. AIがシナリオの土台とGM向け進行ガイドを生成する
3. GMが生成内容を確認し、必要に応じて調整する
4. GMが導入シーンの読み上げ文章を使ってセッションを始める
5. プレイヤーは状況に応じて行動や選択を行う
6. GMはシーンごとの進行ガイドを参考に、状況説明、NPCの演技、情報の提示を行う
7. プレイヤーが手がかりを集め、イベントを体験する
8. 真相へたどり着き、行動や選択の結果に応じたエンディングを迎える

生成される内容は、以下を想定しています。

* 導入
* シーンごとの進行
* 登場人物（NPC）
* 手がかり
* イベント
* 真相
* エンディング候補
* GM向け進行ガイド

ユーザーは既存シナリオを探すことなく、GMが当日に行うことを確認しながら、短時間で遊び始めることができます。

### 5-2. それでも自分が作りたい理由

私は、単にシナリオを生成するサービスを作りたいのではありません。

シナリオを用意するだけでは、GM未経験者が「どのように進めればよいか分からない」という問題が残ります。

そこで、シナリオの内容に加えて、各シーンでGMが行うことやプレイヤーへの問いかけ方まで提示し、物語体験を始める最初の一歩を後押しするサービスを作りたいと考えています。

### 5-3. 差別化を体験価値で表現する

既存サービスが物語生成そのものやシナリオ販売を提供するのに対し、本サービスは、**「物語を作りながら遊ぶ体験を、初心者でも手軽に始められること」**に価値を置いています。

ユーザーはシナリオを探したり、生成AIへの詳しい指示を考えたりすることなく、条件を入力するだけで、シナリオとGM向けの進行ガイドを用意できます。

さらに、各シーンには以下の情報を含めます。

* シーンの目的
* 想定時間
* GMが説明する内容
* GMが行うこと
* プレイヤーへの質問例
* 入手できる手がかり
* NPCの反応
* 次のシーンへ進む条件
* 進行が止まった場合のヒント

私はシナリオ生成サービスを作りたいのではなく、**初心者が実際にセッションを始められる状態を作るサービス**を目指します。

### 生成例

#### 入力

* ジャンル：ミステリー
* 世界観：現代日本
* 雰囲気：シリアス
* プレイ人数：4人
* プレイ時間：2時間

#### 出力

### シナリオタイトル

消えた遺言書

### 導入

資産家が亡くなった翌日、書斎に保管されていた遺言書が消失した。

参加者は、屋敷に集まった関係者として事件の調査を行う。

### 登場人物（NPC）

* 執事
* 資産家の長女
* 顧問弁護士

### 手がかり

* 防犯カメラ映像
* 書斎の鍵
* 破られた封筒

### イベント

* 屋敷全体で停電が発生する
* NPC同士の証言が食い違う
* 書斎から新たな証拠が見つかる

### 真相

長女が相続問題を隠すため、遺言書を持ち出していた。

### エンディング候補

* 真相を解明し、遺言書を取り戻す
* 誤った人物を犯人としてしまう
* 犯人を特定できないまま事件が終わる

### シーン1：依頼と事件説明

**シーンの目的**

プレイヤーに事件の概要と調査の目的を伝える。

**想定時間**

10分

**GMが読み上げる文章**

「資産家である山城源一郎が亡くなった翌朝、書斎から遺言書が消えていることが判明しました。昨夜、屋敷にいたのは皆さんと三人の関係者だけです」

**GMが行うこと**

* 屋敷と事件の状況を説明する
* 登場人物を紹介する
* プレイヤーに調査を依頼する

**プレイヤーへの質問例**

* 最初に誰から話を聞きますか
* 書斎を調べますか
* 昨夜の出来事を確認しますか

**次のシーンへ進む条件**

プレイヤーが調査する場所または話を聞くNPCを決める。

### シーン2：屋敷の調査

**シーンの目的**

事件の真相につながる手がかりを集める。

**想定時間**

40分

**GMが行うこと**

* プレイヤーが選んだ場所の状況を説明する
* 行動に応じて手がかりを提示する
* NPCへの質問に対して、それぞれの立場に応じた回答をする

**調査できる場所**

* 書斎
* 廊下
* 長女の部屋

**入手できる手がかり**

書斎では、破られた封筒を発見できる。

廊下では、停電直前の防犯カメラ映像を確認できる。

長女の部屋では、書斎の予備鍵を発見できる。

**プレイヤーが迷った場合のヒント**

「書斎の机には、まだ詳しく調べていない引き出しがあります」

### シーン3：停電

**シーンの目的**

物語に変化を加え、新しい証拠を提示する。

**発生条件**

手がかりを二つ以上発見する。

**GMが読み上げる文章**

「突然、屋敷中の照明が消えました。暗闇の中で何かが倒れる音が響きます」

**GMが行うこと**

* 停電の発生を説明する
* NPCの動きを伝える
* 新しい証拠につながる状況を作る

### シーン4：推理

**シーンの目的**

集めた手がかりを整理し、プレイヤーに真相を考えてもらう。

**GMが行うこと**

* 発見済みの手がかりを確認する
* プレイヤー全員に意見を聞く
* 犯人、動機、遺言書の場所を質問する

**プレイヤーへの質問例**

* 遺言書を持ち出した人物は誰だと思いますか
* その人物が持ち出した理由は何だと思いますか
* どの手がかりがその推理を裏付けていますか

### シーン5：エンディング

プレイヤーの推理や行動に応じて、エンディングを分岐させる。

## 7-2. MVPで検証したいこと

### ① 準備負担を減らせるか

物語体験に興味はあるものの、準備の負担によって遊べていなかった人が、AIによって生成されたシナリオを利用し、短時間で遊び始められるかを検証します。

### ② GM未経験者でも進行できるか

各シーンの目的、GMが行うこと、プレイヤーへの質問例、シーンの移行条件などが提示されることで、GM未経験者でもセッションを進行できるかを検証します。

### ③ GMの準備負担を減らせるか

生成された導入、NPC、手がかり、イベント、シーンごとの進行ガイドを利用することで、GMが事前に考える内容を減らせるかを検証します。

### ④ 最初の一歩を後押しできるか

物語体験に興味を持っていた人が、「これなら自分でも遊べそう」と感じ、実際に友人とのセッション開催へ踏み出せるかを検証します。

## 8. このアプリの懸念点とその対策

### 懸念点①

生成されたシナリオが、実際には遊びにくい可能性がある。

#### 対策

* テストプレイを実施する
* 利用者からフィードバックを収集する
* プロンプトを改善する
* シーンごとの目的と進行条件を明確にする

### 懸念点②

GM向け進行ガイドが、実際のプレイヤーの自由な行動に対応できない可能性がある。

#### 対策

* 一つの正解だけを指定しない
* 想定される複数の行動例を生成する
* 進行が止まった場合のヒントを用意する
* GMが内容を調整して利用することを前提とする

### 懸念点③

既存の生成AIとの差別化が難しい可能性がある。

#### 対策

* 初心者向け入力フォームを用意する
* GM向けに情報を構造化して出力する
* シーンごとにGMが行うことを提示する
* シナリオ生成ではなく、遊ぶための準備支援に特化する

### 懸念点④

著作権に関する問題が発生する可能性がある。

#### 対策

* 特定作品の再現を目的とした利用を想定しない
* オリジナル設定を生成するプロンプトを設計する
* 利用規約に生成物の取り扱いを明記する
* 既存作品の再現利用を推奨しない

* Ruby on Rails

* PostgreSQL

#### デプロイ

* Render

#### ライブラリ・外部サービス

* OpenAI API
* Sorcery
* Kaminari

### 今回チャレンジしたい点

* OpenAI APIを利用したシナリオ生成
* AI出力の構造化
* シーンごとのGM進行ガイドの生成
* シナリオ管理機能

### 不安な点

* プロンプト設計
* 生成品質の安定化
* シーン同士の整合性
* API利用料金

### 10-2. 技術選定の比較検討

| 候補            | 採用 / 不採用  | 理由                             |
| ------------- | --------- | ------------------------------ |
| Ruby on Rails | 採用        | RUNTEQで学習しており、短期間でMVPを開発しやすいため |
| Laravel       | 不採用       | PHPの学習コストが発生するため               |
| Django        | 不採用       | Pythonの経験が少なく、開発期間内での習得が難しいため  |
| PostgreSQL    | 採用        | Renderとの相性が良く、本番環境でも利用しやすいため   |
| MySQL         | 不採用       | PostgreSQLを優先して利用するため          |
| Render        | 採用        | Railsアプリを比較的素早く公開できるため         |
| AWS           | 将来的に採用を検討 | 本リリース後にインフラ構築の経験を深めるため         |

### 10-3. キャッチアップ不足の懸念

OpenAI APIを利用した開発経験がないため、学習コストが発生する可能性があります。

また、シーンごとの進行、NPC、手がかり、イベント、真相を矛盾なく生成するためには、AIへの指示内容や出力形式を工夫する必要があります。

そのためMVPでは、以下の機能に範囲を絞ります。

* シナリオ生成
* シーンごとのGM進行ガイド生成
* シナリオ保存
* シナリオ一覧
* シナリオ詳細閲覧

NPCの会話追加、シーンの再生成、セッション中の進行管理などは本リリース以降の機能とします。

MVPでは、**「準備や進行への不安を減らし、初心者でも物語体験を始められるか」**という価値の検証を優先します。
